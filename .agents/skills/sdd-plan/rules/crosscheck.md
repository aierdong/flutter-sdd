# 对证：spec 与 plan 的语义核对

`plan_lint` 核得到「第 1 节有没有一句对应 R5」，核不到「那句和 R5 说的是不是一回事」。
这一层补的就是这个缺口。

## 为什么需要它

p00-001 的真实漏点：第 1 节写「没有表时保留表头并显示提示」，而 R4 要求表体显示
`该 schema 下暂无表。`，且空态不能出现 `0 张表`。引文逐字可查，lint 全过，
人读到的画面里却没有这句文案。

漏法可以归成三类，处理方式不同：

| 漏法 | 例子 | 谁拦 |
|---|---|---|
| 整条 R 没进第 1 节 | R9 滚动、R10 无选中态只在「代价」里 | `plan_lint` L11 |
| 同一条 R 只写了一半 | 「切换升降序」丢了 `▲`/`▼` | 本文件 |
| 写了但读不出后果 | 覆盖了页头高度，第 1 节没写"两行" | 本文件 |

## 三条硬约束

**一、换上下文。** 新开 subagent 或新会话，只喂 `spec.md`、`plan.md`、本文件。
不喂访谈记录、前一版 plan、写 plan 时的推理。写 plan 的 Agent 已经知道自己"想写什么"，
在同一个上下文里会把「按状态显示」读成"已经说清了"，把「可切换升降序」读成"方向也说了"。

**二、每条结论交两段引文。** spec 的行号 + 原文，plan 的行号 + 原文。
引文必须逐字来自文件，不能概括。交不出引文的判 `UNVERIFIABLE`，按不通过处理——
这一条是防它用"看起来没问题"填空。

**三、只报缺口。** 全过就一句「对证无缺口」，不写通过清单、不打分、不列"已检查 N 条"。
一份读起来很完整的审查报告会变成新的必读材料，审核怪圈就是这么回来的。

## 五条规则

| 编号 | 判什么 | 不满足时 |
|---|---|---|
| `V1` 落点一致 | 「覆盖核对」里每条非「无」的行，把 R 原文与落点并排读，判断是不是同一件事 | 写清缺哪一部分 |
| `V2` 覆盖有后果 | 2.1 每条 `覆盖`，第 1 节必须有体现它造成的可见差别 | 写出缺的那句画面 |
| `V3` 多态不打架 | spec 有多种状态时，第 1 节每态一句，且不能互相矛盾 | 指出哪两态读起来一样或相反 |
| `V4` 拍板对得上 | 「需要你拍板」与 2.1 条目一一对应，既不复述也不漏 | 列出错位的那条 |
| `V5` 不做没写成会做 | spec 第 5 节「明确不做」每条，第 1 节不得写成将要发生 | 引出那句 |

`V1` 的判据是「界面上能不能看到」，而不是「说得对不对」。
R 的「可观察证据」那一行就是按这个标准写的，直接拿它对照。

## 输出格式

```
V3  R4   spec:88「仍渲染六列表头；表体显示 `该 schema 下暂无表。`」
         plan:10「没有表时保留表头并显示提示」
         缺：空态的具体文案；以及 `6 张表` 在空态应当消失

V2  UI-03  plan:31「页头 56 高，左侧两行文字」
           plan:10「左上两行显示当前连接和 schema」
           缺：第 1 节写的是"两行"不错，但没和"不是 36 高单行工具栏"对上，
               人看不出这条覆盖批的是什么
```

没缺口：

```
对证无缺口
```

## 不做的事

- 不评价方案好坏，不推荐别的走法。那是阶段 3 的事，现在要改得回阶段 3。
- 不给分数、不列通过项。
- 不重写 plan，只指出缺哪条、缺什么。

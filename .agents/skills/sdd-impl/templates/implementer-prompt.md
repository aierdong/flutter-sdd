# 实现任务组委派提示词

本模板只供主 Agent 委派子 Agent 执行一个实现任务或一组相关实现任务时填写和发送。检查任务按 plan 指定的执行者处理，不使用本模板。主 Agent 自己执行时不使用，也不强制每个任务都委派。

主 Agent 先依据 plan 理清依赖，再按共享上下文和文件边界分组，最后判断不同组能否并行。主 Agent 保留任务排序、检查安排、进度勾选、否决次数记录和用户交接责任。主 Agent 在发送前删除占位说明，提供目标文件的路径与相关条款；子 Agent 读取分组所需的原文，不以主 Agent 的摘要代替已批准文档。

## 主 Agent 提供

- spec 位置：`specs/pNN-NNN-<slug>/spec.md`；版本及已批准状态：<填写>。
- plan 位置：`specs/pNN-NNN-<slug>/plan.md`；已批准状态：<填写>。
- 本组任务：<逐项填写 T 编号、原文及组内依赖顺序；仅一项时照写>。
- 对应需求：<逐项填写 R 编号及位置>。
- 已确认方案、适用规范和例外：<填写原文位置>。
- 组外前置任务及可用产物：<填写；未完成的依赖不能交给本组假定已完成>。
- 已知影响文件、共享资源与不碰范围：<填写；并行时明确各组文件所有权与交接边界>。
- 允许新增必要辅助文件的条件：仅服务于本组已有任务，不改变需求、方案或授权范围；新增前核对与并行组的文件所有权，新增后报告用途。
- 本组检查边界：检查任务另按 plan 指定的执行者安排，本实现委派不包含检查；子 Agent 不自行运行测试、编译、静态检查或 lint。
- 已有检查结果及适用条件：<只作改动背景；没有则写“无”>。
- 现有工作区改动和并行组注意事项：<填写；没有则写“无”>。

## 子 Agent 执行

1. 子 Agent 先读仓库的 `AGENTS.md`、`steering.md` 和 `.agents/skills/sdd-impl/SKILL.md`，再读指定的 spec、plan、本组相关的索引规范与现有文件。不批量读取无关材料。子 Agent 按组内依赖顺序完成已委派任务，不另定需求、方案、检查或审查步骤。具体局部写法可自行选择，但必须遵守已确认协作边界。
2. 子 Agent 不强制测试驱动开发，不运行或附加测试、编译、静态检查、lint、手工验收或逐任务审查。本模板只委派实现任务或主 Agent 指定的修复；检查任务由 plan 指定的另一执行者另行处理。
3. 子 Agent 的交付是改动完成，不是验收通过。任务无法继续时（缺少前置产物、入口不可用、与已确认方案冲突），停止并报告原因，不替代检查任务。主 Agent 要求修复某个失败问题时，告知本次会话的否决次数；子 Agent 在既定范围内完成指定修复后报告，由主 Agent 安排检查和计数。第三次否决后子 Agent 不继续自动修复。
4. 子 Agent 发现任务必须改变需求、方案、验收条件或授权范围时停止并报告。子 Agent 不改 spec、plan 的任务勾选或其他上游内容，不创建提交，不自动回滚已有改动。
5. 子 Agent 完成后报告每项任务的实际改动、辅助文件用途及遗留问题。子 Agent 不声称改动完成即验收通过，也不宣称整个 spec 完成。

## 返回格式

- 任务：<逐项列出 T 编号及状态：改动完成 / 受阻 / 未完成>。
- 实际改动：<按任务列路径及作用；必要辅助文件注明用途；没有写“无”>。
- 检查：未执行；检查任务由主 Agent 按 plan 指定的执行者另行安排。
- 修复：<被要求修复时按独立问题列已完成改动及主 Agent 告知的否决次数；没有写“无”>。
- 遗留事项：<需要主 Agent 或用户处理的具体问题；没有写“无”>。

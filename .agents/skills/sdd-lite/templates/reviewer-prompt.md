# 轻量交付独立审查提示词

主 Agent 填写以下内容后，交给一个全新的审查子 Agent。主 Agent 不恢复或复用参与过本次编写、实现、验证或失败调查的会话。

---

本次任务是轻量交付的独立审查。只读核对并返回完整结论，不修改任何文件，不运行测试、构建、启动、格式化、静态扫描或 lint，不派其他核查者，不调用 `sdd-review`。本次审查不要求 `plan.md`、`grill.md` 或 `review.md`。

## 输入

- 技能说明：<sdd-lite/SKILL.md 的路径>
- 轻量记录：<目标 spec.md 的路径和当前版本>
- 实际改动范围：<改动文件、职责及必要辅助文件>
- 已有或其他任务的改动：<本次开始前已存在的范围；没有则写无>
- 验证结果及来源：<各 V 的动作、范围、预期、关键结果，以及本次执行或复用的适用依据>
- 用户验收：<用户已明确确认的项目和原意；没有则写无>
- 已知未完成事项：<无，或具体内容>
- 本轮性质：<首次完整审查 / 修复后的定向复核及原问题处理说明>

## 核对方法

1. 完整读取技能说明、轻量记录，以及项目入口和知识索引。按索引读取直接相关规范，按本次范围读取实际成果及直接依赖，不开展全仓库体检。
2. 确认流程为 lite，状态为 approved，版本与交接一致。缺少批准、版本不一致或范围无法界定时，如实报告，不推测通过，也不要求用户在审查中补确认。
3. 从每条需求 R 出发核对实际落点、条件、行为和结果。文档交付核对实际内容，不因文件存在就判为完成。
4. 核对实际成果是否遵守边界、已批准做法和适用规范，并检查本次改动及直接相关路径中的具体缺陷。不重新选择最优方案，不根据偏好增加要求或验证系统。
5. 逐项核对约定验证 V 的动作、范围、预期、结果来源和当前适用性。用户验收必须有用户本人的明确确认；其他执行者不能代替。没有结果、结果失效或动作不匹配时，不视为通过，不代跑。
6. 区分内容阅读、代码阅读、自动验证与用户验收的证据强度，不把一种依据包装成另一种。必要辅助文件和局部写法不同不自动构成越界，必须指出实际影响了哪项要求、边界或代价。
7. 有原审查问题时，保留编号，核对原问题、修复的直接影响和因此失效的结果。不默认全量重审；要求或范围实质变化导致原结论失效时，说明需要重新核对的范围。

## 返回内容

任务结束时一次性返回完整结果，不提前发送片段作为最终结论：

- 实际成果：一句话说明已实现的用户结果。
- 审查范围：实际读取的成果、直接依赖和未核对内容。
- 逐条需求判断：每个 R 写符合、不符合或无法核实，附实际路径、行号或可定位段落及依据。
- 约定验证核对：每个 V 是否有满足预期且仍适用的结果，说明来源和限度。
- 问题与核实限制：按 Q1、Q2 编号，写级别、状态、依据、影响及修正或核实目标；没有则写无。
- 结论：通过、不通过或受阻，附理由和问题数量。
- 后续位置：无、第一段重新确认、原批准范围内修复或补齐结果，或建议升级完整流程；无法判断时说明缺什么。
- 执行声明：本阶段未执行测试或其他验证命令，引用的是已有结果。

问题级别使用“必须解决”“轻微问题”“无法核实”。必须解决项未解决时结论为不通过；没有已证实问题但关键事实不足时为受阻；只有要求均有符合依据、约定验证满足、没有影响通过的遗留问题时才为通过。

审查结论不是用户选择，不请求用户确认。审查完成后结束，不修复、不修改状态、不启动下一轮。主 Agent 负责将结果忠实写入轻量记录第 5 节。

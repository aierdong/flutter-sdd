# Grill 决策日志：p00-001-schema-tables-page

访谈对象：需求提出者。类型：`new`。上游：无。问题数：13。第 12–13 条由「全英文界面」这条回答派生（规范冲突与拆分顺序），没有展开新维度，但超出新建上限 1 条，记录在此以便回看。

## 决策

Q1 这个页面和应用现有入口是什么关系？
A: 替换计数器，删掉模板页与计数器测试，应用启动即进入该页面。
   放弃：保留计数器入口、页面只在测试里渲染。
   何时重新评估：无。
→ R1 / §5

Q2 表格每行显示哪些列？
A: 表名、类型、描述（comment）、列数、行数（估算）、大小；不要所有者。
   放弃：所有者、精确行数。
   何时重新评估：需要定位对象归属时加 owner 列。
→ R3

Q3 用户怎么知道当前表格是哪个 schema 下的表？
A: 头部显示两级：第一行「连接名 · 库名」，第二行 schema 名。
   放弃：只在表格上方写一行 schema、或完全不显示 schema。
   何时重新评估：出现 schema 切换器时，schema 名改为可交互控件。
→ R2

Q4 纯 UI spec 要覆盖哪些页面状态？
A: 加载中、空、失败三态都做，页面接收状态对象用假数据渲染；失败态展示错误码。
   放弃：只做「有数据」或「空 + 有数据」的最小范围。
   何时重新评估：若数据层改为同步取数，可去掉加载态。
→ R4 / R5 / R6

Q5 点击 New Connection 后发生什么？
A: 按钮可见但置灰不可点，本 spec 不定义点击行为。
   放弃：占位对话框、SnackBar 提示。
   何时重新评估：新建连接 spec 启动时。
→ R2 / §5

Q6 表格行需要哪种交互？
A: 纯展示，无选中、无悬停高亮。
   放弃：单选高亮、hover 高亮。
   何时重新评估：表详情 spec 需要选中入口时。
→ R11 / §5

Q7 表很多、表名很长、窗口变窄时表格如何表现？
A: 纵向滚动 + 横向滚动，文本不截断。
   放弃：省略号 + tooltip、分页、虚拟滚动。
   何时重新评估：窄窗口成为常态，或行数超过数千。
→ R10 / §5

Q8 反向检查：搜索框、刷新、列排序、数量统计、右键菜单、导出现在要不要？
A: 要列排序与表数量统计；搜索、刷新、右键菜单、导出都不要。
   放弃：搜索/过滤、刷新按钮、右键菜单、CSV 导出。
   何时重新评估：表数量大到需要定位时加搜索。
→ R8 / R9 / §5

Q9 哪些列可以排序？
A: 除描述外 5 列可排序，数值列按数值比较。
   放弃：描述列排序、仅表名排序。
   何时重新评估：描述参与检索或排序时。
→ R8

Q10 页头的连接信息用什么文案？
A: 「名称 · 库名」，如 `Local dev · myapp`，不含主机与端口。
   放弃：仅名称、名称 + host:port/库名。
   何时重新评估：同名连接指向不同主机且需要区分时。
→ R2

Q11 界面文案用什么语言？
A: 全英文。
   放弃：中文为主、英文标签 + 中文说明、i18n 框架。
   何时重新评估：需要多语言时。
→ R2–R6 / §6

Q12 全英文与 FSD-08 固定中文「（错误码：…）」格式冲突，怎么处理？
A: 失败文案改为英文 `(Error code: FSD-XXX-NNN)`，同步修改规范 FSD-08 与断言，规范升 v2。
   放弃：失败行保留中文错误码格式的例外方案。
   何时重新评估：规范变更波及日志、错误消息等其他条款时。
→ R6 / R7

Q13 UI spec 与 FSD-08 v2 怎么拆、谁先？
A: 并成一个 spec，一次性改完（用户明确选择）。
   放弃：「规范先行」与「UI 先行 + 记录临时例外」两种拆法，以及「一 spec 一问题」的默认流程约束。
   何时重新评估：规范变更超出 FSD-08 文案格式时，拆出独立 spec。
→ R7 / §6

## 1. 背景与问题

**现状**：仓库是 `flutter create` 生成的骨架。`lib/main.dart` 仍是计数器模板，`test/widget_test.dart` 是配套的计数器冒烟测试；`lib/` 下没有页面、领域模型或数据层，`specs/` 为空。`project.md` 定义的「database → schema → table 树 + 表详情」尚未有任何实现。`docs/standards/coding.md` 的 FSD-05 要求首个 spec 交付前删除或替换计数器页与测试（`coding.md:163`）。

**问题**：现在运行应用只能看到计数器，看不到任何表；后续「接数据层」的 spec 也缺少一个能容纳表列表的页面骨架，先做数据层同样没有地方展示。同时，FSD-08 把失败文案格式固定为中文的「（错误码：…）」，并要求测试断言 `find.textContaining('错误码：')`（`coding.md:226`），与本 spec 选定的全英文界面直接冲突——不先解决，UI 一交付就会被判不合规。

**为什么现在做**：它是 p00 的第一个 spec，同时决定页面骨架和失败文案规范；拖到后面做，就要同时改页面与规范两处，还要处理已交付文案的迁移。

**上游**：无。**影响面**：现有计数器页与其测试、代码规范 FSD-08 的失败文案格式（含审计动作 A4 的相关检查、`steering.md` 的版本标注）。

## 2. 目标

- 让应用启动即呈现「单 schema 表列表」页面：连接与 schema 两级标题、New Connection 按钮、表列表。
- 让页面用同一套结构呈现加载中、空、失败三种状态，而不是只画「有数据」那一种。
- 让用户能在页面内按列排序，并看到当前 schema 的表数量。
- 让失败文案与升级后的规范一致：英文格式、包含 `FSD-` 错误码。

**成功后，你能看到/做到**：运行应用，页头写着「连接名 · 库名」和 schema 名，下面是一张表列表与「N tables」；点表头能改顺序；没有表时看到提示而不是空表格；失败时看到一句英文错误和 `FSD-` 开头的错误码。

## 3. 用户场景

### 场景 A：浏览并按行数排序

1. 开发者启动应用（macOS 或 Windows），应用直接进入浏览页，不再出现计数器。
2. 页头显示 `Local dev · myapp`，下一行显示 `public`，同一区域有置灰的 `New Connection` 按钮。
3. 表格显示 6 列与若干行，附近显示 `12 tables`。
4. 点击 `Est. rows` 表头，行按估算行数从少到多；再点一次变成从多到少；点击 `Table name` 表头则改为按名字升序。
5. 把窗口拉窄到看不全所有列，左右滚动后仍能读到完整的表名与大小。

### 场景 B：schema 下没有表

1. 传入的表列表为空。
2. 表格区域显示 `No tables in this schema.`。
3. 既没有表头，也没有数据行和数量统计；加载中与失败态的呈现不会和它混淆。

### 场景 C：加载中与失败

1. 数据还没到：表格区域显示进度指示，没有表格，也没有数量统计。
2. 数据加载失败：表格区域显示 `Could not load tables (Error code: FSD-TABLE-001)`，没有表格，也没有数量统计。
3. 用户不需要刷新按钮——本 spec 不提供重试入口。

## 4. 必须做到

- [ ] **R1** 应用启动后直接呈现本 spec 的浏览页，界面上不再出现计数器。
  - **反例**：启动仍是计数器；页面存在但需要点击才出现；home 仍指向模板页。
  - **可观察证据**：运行应用首屏即页头与表格区域；应用内找不到计数器的加号按钮与计数文案。

- [ ] **R2** 页头第一行显示 `<连接名> · <库名>`，第二行显示 schema 名；`New Connection` 按钮在同一页头区域可见且点击不产生任何界面变化（无对话框、无提示、无跳转）。
  - **反例**：只显示连接名；schema 名缺失或被写死成 `public`；按钮可点并弹出空壳对话框。
  - **可观察证据**：页头文本随传入的连接名、库名、schema 名变化；点击按钮后界面无任何变化。

- [ ] **R3** 传入 N（N > 0）张表时，表格每行对应一张表，列固定为 `Table name`、`Type`、`Description`、`Columns`、`Est. rows`、`Size`，取值来自传入数据。
  - **反例**：行数与 N 不符；缺列或多列；`Description` 为空时该行消失或整页报错；内容来自页面内硬编码而非传入。
  - **可观察证据**：换一份表数据渲染，行数、表名与各字段值随之改变。

- [ ] **R4** 已加载但表数为 0 时，表格区域显示空状态提示，不渲染表头、数据行与数量统计。
  - **反例**：显示只有表头的空表格；显示 `0 tables`；空态与加载态看起来一样。
  - **可观察证据**：屏幕上只有空状态提示。

- [ ] **R5** 加载中时，表格区域显示进度指示，不显示表格与数量统计。
  - **反例**：加载中显示空白表格或旧数据；进度指示出现在表格之外的其他区域。
  - **可观察证据**：进度指示可见，表格与计数不可见。

- [ ] **R6** 失败时，表格区域显示 `<消息> (Error code: FSD-<AREA>-<NNN>)`，不显示表格与数量统计。
  - **反例**：只显示消息没有错误码；错误码不在同一段文案里；失败时仍显示表格；括号或冒号格式与规范不一致。
  - **可观察证据**：文本包含 `Error code: FSD-`。

- [ ] **R7** 本 spec 交付时，代码规范的 FSD-08 失败文案格式与测试断言改为英文 `<消息> (Error code: FSD-<AREA>-<NNN>)` 与 `find.textContaining('Error code:')`，规范版本升为 `v2`，`steering.md` 的版本标注同步为 `v2`。
  - **反例**：规范仍要求中文「（错误码：…）」；只改了规范正文没改索引版本；版本仍标 `v1`。
  - **可观察证据**：规范顶部版本为 `v2`；全文搜索不到旧的「错误码：」格式要求；`steering.md` 索引行标 `v2`。

- [ ] **R8** 有数据时，`Table name`、`Type`、`Columns`、`Est. rows`、`Size` 五列表头可点击，点击在升序与降序间切换并显示当前排序方向；数值列按数值比较，文本列按字典序比较；`Description` 表头不可点击；默认按 `Table name` 升序。
  - **反例**：点 `Description` 也排序；`Size` 按 `1.2 MB` 字符串比较；同一列连续点击顺序不变或方向标错；默认顺序是传入顺序而不是表名升序。
  - **可观察证据**：点击表头后行的顺序变化，且排序方向标记随之切换。

- [ ] **R9** 有数据时显示表数量文案 `N tables`（N 等于渲染出的行数；N 为 1 时显示 `1 table`）；加载中、空、失败态都不显示。
  - **反例**：N 与行数不一致；1 张表显示 `1 tables`；空态显示 `0 tables`。
  - **可观察证据**：文本与行数逐例对照。

- [ ] **R10** 表很多（如 500 行）、表名或描述很长、窗口变窄时，表格区域可纵向滚动；列总宽超出时横向滚动；单元格文本不截断；窗口变窄不出现布局溢出错误。
  - **反例**：窄窗口出现黄黑溢出条或抛异常；长表名显示省略号；横向无法滚动导致右侧列被裁掉。
  - **可观察证据**：拖动横向滚动后能读到完整表名；缩窄窗口后界面无溢出提示。

- [ ] **R11** 点击或悬停数据行不产生选中态、不导航、不改变数据。
  - **反例**：行出现高亮或选中标记；点击行打开详情、对话框或新路由。
  - **可观察证据**：点击行前后界面无变化，路由不变。

## 5. 明确不做

- 不做新建连接表单、对话框或页面——按钮置灰。理由：本 spec 只画 UI，连接管理留给后续 spec。
- 不做搜索/过滤、刷新按钮、右键菜单、导出 CSV。理由：首版未选入，避免把浏览页做成工具箱。
- 不做行选中、悬停高亮、表详情/字段/约束/外键面板。理由：详情是后续 spec，本 spec 保持纯展示。
- 不做列宽拖拽、列顺序调整、列显隐。理由：内置组件不提供，且不在首版；需要时另行决策。
- 不做分页与虚拟滚动。理由：500 行以内桌面滚动足够，性能在 `project.md` 的取舍里排最后。
- 不做深色/浅色主题切换与 i18n 框架。理由：文案固定英文，引入 i18n 会扩大范围。
- 不做真实数据库连接、元数据查询、排序结果持久化。理由：本 spec 明确只做 UI，数据由调用方传入。
- 不改变 `flutter analyze` / `flutter test` 的命令入口，也不改变代码规范中除 FSD-08 文案格式以外的条款。理由：回归保护，避免顺手改规范。

## 6. 风险与取舍

| 决策 | 选择 | 理由 | 放弃了什么 | 何时重新评估 |
|---|---|---|---|---|
| 页面状态覆盖面 | 加载中、空、失败都做 | 接数据层时页面不用重写 | 更少的 widget 与状态建模 | 数据层若改为同步取数 |
| `New Connection` | 置灰不可点 | 没有表单可去，假交互会误导 | 点击反馈 | 新建连接 spec 启动时 |
| 行交互 | 纯展示 | 详情面板不在本 spec | 后续需另加选中态 | 表详情 spec |
| 排序范围 | 除描述外 5 列，默认表名升序 | 描述通常最长且不参与比较 | 描述排序、自定义排序 | 用户要求按描述排序时 |
| 溢出策略 | 双向滚动、文本不截断 | 保证信息完整 | 省略号 + tooltip 的紧凑布局 | 窄窗口成为常态时 |
| 大小格式 | 人类可读单位（B/KB/MB/GB），排序按字节 | 表格里直接可读 | 精确字节数 | 需要精确数值时 |
| 依赖 | 只用 Flutter 内置组件，不新增第三方库 | FSD-12 要求；内置表格组件足够 | 列宽拖拽、虚拟滚动 | 500+ 行出现性能问题 |
| 文案语言 | 全英文 | 用户选择 | 中文可读性 | 需要多语言时 |
| 规范变更并入本 spec | 同一 spec 改 FSD-08 为 `v2` | 用户明确选择；英文错误码是 UI 交付前提 | 「一 spec 一问题」、规范变更独立可审 | 规范变更波及更多条款时拆出 |

## 7. 审阅问题

**必须你决定**：

1. `analysis_options.yaml` 的 FSD-11 严格配置（strict-casts / strict-inference / strict-raw-types 与 lint 列表）目前是 Flutter 默认（`analysis_options.yaml:12-31`），要不要并入本 spec？
   - A. 不并入：本 spec 只做 UI + FSD-08 文案格式；FSD-11 在本 spec 的审查中只按 `dart format` / `flutter analyze` / `flutter test` 三条命令判定，严格配置留给后续 spec。
   - B. 并入：本 spec 同时补齐 `analysis_options.yaml` 并修掉由此暴露的告警；审查可按 FSD-11 全文判定，但本 spec 的范围会再扩大一块。

**建议确认**：

- 空态我按「整块替换表格」写进 R4（不保留表头）；若希望保留表头，请在批准时说明。
- 排序只做升/降两态，没有「取消排序」的第三态；默认按表名升序（R8）。
- 数量文案做单复数：`1 table` / `N tables`（R9）。

## 1. 方案摘要

**用户会看到的变化**：

- 应用打开后仍是单 schema 的表列表；页头仍显示连接名、数据库名、schema 和禁用的「新建连接」，但按钮及页面外观换成 shadcn 风格。
- 有数据时仍是六列表格和 `N 张表`，五列表头仍可按原有规则排序；空数据时仍保留六列表头和原提示。整张表格采用 shadcn 原生组件，允许它自带的悬停外观和视口处理，不再要求旧表格逐像素样式或同时构建全部行；数据行不增加点击选中和导航。
- 加载时表格区显示 shadcn 的进度指示；失败时仍只在表格区显示消息和错误码。四态互斥、页头始终可见，原有数据与文案不变。
- 系统浅色、深色模式在启动时与运行中均决定整页外观；用户无须重启，也看不到主题开关。
- 系统模式变化后，当前数据、排序列和方向以及横向、纵向滚动位置仍在；500 行仍能滚到最后一行，在 800×600 窗口横向滚动后能看完整的长表名与描述，页面不溢出。

**怎么做到**：应用入口继续提供固定演示数据和四态启动参数；组合根更换为 shadcn 应用根并配置浅色、深色主题与系统跟随。页面继续持有原有排序状态及外部传入的页面状态；现有表格视图负责把排序后的行、六列表头和空态映射到 shadcn 表格，表头仍把排序动作交还页面。滚动位置由持续存在的页面/表格滚动状态维护，主题变化只改变呈现，不触发数据获取。

**为什么这么切**：沿用现有排序控制器、演示输入与互斥页面状态，只迁移呈现层；不引入第二套状态管理、不为了复刻旧表格而关闭 shadcn 原生能力，也不引入 Material/Cupertino 兼容层。

**代价**：新表格的行悬停、尺寸、颜色、装饰和视口行为可能与旧版不同；须重新核对长文本、空态、排序与双向滚动。系统模式的运行中切换和桌面视觉需要在实际桌面环境核对；自动测试不能代替这一检查。

**需要用户决定的事项**：见 2.1 中的规范覆盖及沿用边界；请在方案确认（A）时核对，不增加新的产品选择。

## 3. 设计

### 3.1 结构与数据流

- 组合根仍读取 `DEMO_STATE` 并把现有演示连接信息、六张表或互斥的空、加载、失败状态交给页面。组合根改用 shadcn 应用根；浅色、深色主题交给它按系统模式选择，不在用户界面增加开关。原 `PgTable`、失败对象和启动参数含义不变。
- 主题层只负责给应用根提供 shadcn 的浅色和深色主题。页面背景、页头文字、数量和错误文字随应用主题变化，不能从原 Material 主题或固定浅色值取色。只迁移组件自身配色；其余页面布局仍受第 2.1 节的边界约束。
- 页面仍从调用方接收连接信息与互斥页面状态，保留原排序控制器及其五列比较规则。加载态只显示 shadcn 进度指示；失败态只读取消息和错误码。有数据时，页面把已排序的记录、当前列和方向传给表格视图；空数据时也传入同一视图以保留六列表头。
- 表格视图以 shadcn 表格组件绘制表头、数据单元格和空态表体；只给五个既有可排序表头连接排序动作，不给描述列或数据行增加选择、导航或详情逻辑。横纵滚动的状态与页面状态保持同一生命周期；主题改变时只重新绘制，不销毁排序控制器、表格的滚动状态或输入记录。保留 shadcn 原有的悬停、滚动及视口处理能力，不用旧测试中「同时构建所有行」的实现方式作为要求。
- 现有 `formatByteSize`、空描述占位与原文案继续用于六列。应用默认六行来自原入口；500 行与长文本由现有测试数据生成并注入页面/视图以核对边界，不伪称桌面启动参数能产生 500 行。

### 3.2 决策

- 沿用第 1 节已确认的「主题由应用根管理、排序留在页面控制器、表格由视图承载」分工；不增加全局状态库或新路由。主题变化与数据状态变化分离，页面状态和排序控制器不因系统亮度变化重新创建。
- 第 2.1 节已经确认迁移组件的原生视觉例外和两区骨架。实现只在该范围内适配可用性；不能通过增添 Material/Cupertino 兼容层或禁用 shadcn 表格能力规避迁移。现有组合根、页面、排序控制器与视图已划定职责，不再访谈结构归属、数据流和复用；上游也已限定失败文案与无数据库边界。UI-01、UI-08、原有页面验收和现有测试入口决定了检查范围，具体分工见第 4、5 节；本次不预留未来通用接口。

## 6. 风险与回滚

#### 新组件与现有可达性不一致
- 风险：shadcn 表格默认视口或尺寸使长字段、末行无法访问，或 800×600 出现溢出。
- 触发信号：T5 的 500 行注入测试不能滚到末行/横向读全字段，或 T6 桌面出现裁剪和溢出。
- 应对：先只调整表格所在区域的约束与滚动状态，保持组件原生能力及第 2.1 节的覆盖；若必须改变已批准的表格原生行为或六列可达要求，则停止返回需求，不暗中换回旧表格。

#### 系统主题切换中断浏览
- 风险：主题改变使页面或表格被销毁，排序、滚动偏移与文字配色不同步。
- 触发信号：T5 模拟亮度变化后偏移或方向复位，或 T6 真实系统切换后视觉一半深一半浅。
- 应对：在已定的主题根、页面和表格生命周期内修复，不新增手动主题状态；若必须改变第 1 节分工才可解决，停止并请用户重新决定方案。

#### 依赖或平台条件不满足
- 风险：所选 shadcn 包与本机 Flutter/Dart 不兼容，或无法在某个平台执行真实桌面核对。
- 触发信号：依赖解析、`flutter analyze`/`flutter test` 失败，或 T6 缺少相应桌面运行入口。
- 应对：在同一组件库内选择兼容版本并更新依赖解析结果；不能满足已确认组件/主题能力时停止交用户决定。平台不可用时报告该平台未运行，不把另一平台和 widget test 结果冒充双平台通过。

#### 撤回范围
- 风险：迁移未完成时留下半套 Material、半套 shadcn 的应用或失效的旧测试。
- 触发信号：T5 静态与自动检查失败且在既定边界内无法恢复。
- 应对：撤销本计划第 3.3 节的依赖、主题、组合根、页面、表格及三个测试文件的本次改动，保留已批准的需求、方案与上游交付；不撤销既有领域数据和排序规则，也不假设必须通过 git 才能撤回。撤回后不得把本 spec 标记为完成。

## 决策

#### Q1：文档交付关系
- 问题：修改原 spec，还是新增一次交付？
- 决定：用户选择新增增量 spec，保留已验收上游。
- 放弃：修订原 spec 并重新批准原需求。
- 何时重新评估：原页面业务目标发生实质改变时。
- 对应：§1 / §6 决策 1。

#### Q2：组件替换范围
- 问题：界面控件与主题根，还是包含基础布局的尽可能全部替换？
- 决定：先选控件与主题根，Flutter 基础布局与文本可保留。
- 放弃：所有基础 widgets 全部替换。
- 何时重新评估：库提供对应组件且确有页面需要时。
- 对应：R1 / §6 决策 2。

#### Q3：上游主题边界
- 问题：原先不做主题切换的原因是什么？
- 决定：原先排除的是页面内手动切换；现在补齐系统模式跟随。
- 放弃：加入用户手动覆盖。
- 何时重新评估：用户要求独立主题偏好时。
- 对应：R3 / §5 / §6 决策 4。

#### Q4：切换时机
- 问题：系统模式在应用运行期间变化时是否立即跟随？
- 决定：运行中跟随，不要求重启。
- 放弃：只在启动时读取系统模式。
- 何时重新评估：无。
- 对应：R3 / R4。

#### Q5：默认外观优先级
- 问题：保持旧布局还是优先采用 shadcn 默认外观？
- 决定：用户先选择 shadcn 默认外观，允许视觉与旧实现不同。
- 放弃：逐像素复刻旧组件。
- 何时重新评估：默认外观导致原有数据不可读时。
- 对应：R2 / §6 决策 2、3。

#### Q6：密度冲突的早期选择
- 问题：当默认尺寸与固定规范冲突时如何处理？
- 决定：用户当时选择保留固定尺寸；后来明确「一切保持 shadcn 默认形态」，以最后的明确指示取代本次早期选择。
- 放弃：最新决定下不再以旧固定尺寸优先。
- 何时重新评估：需要改变全项目长期界面规范时。
- 对应：§6 决策 3。

#### Q7：切换后的浏览位置
- 问题：主题变化时保留排序和滚动吗？
- 决定：用户要求两者都保留。
- 放弃：滚动回到起点。
- 何时重新评估：无。
- 对应：R4。

#### Q8：四态展示
- 问题：迁移后是否允许改动四态文案和区域？
- 决定：四态互斥、区域与文案按原行为保持。
- 放弃：由新组件重定义状态文案和位置。
- 何时重新评估：数据层接入并重新定义页面状态时。
- 对应：R5。

#### Q9：主题设置反向检查
- 问题：是否顺手添加手动主题开关？
- 决定：不添加；只随系统变化。
- 放弃：页面内切换控件与手动覆盖。
- 何时重新评估：用户明确提出应用内偏好时。
- 对应：R3 / §5。

#### Q10：整表替换
- 问题：自定义表格是否也必须替换？
- 决定：用户要求整张表格使用 shadcn 表格组件；这扩展了 Q2 的替换边界，但不要求替换基础布局和文本。
- 放弃：只替换表头交互控件、保留自建表体。
- 何时重新评估：库表格无法满足六列与数据可达性时，须先返回需求阶段。
- 对应：R2 / §6 决策 2。

#### Q11：行视觉
- 问题：数据行默认悬停或选中外观是否允许？
- 决定：允许 shadcn 原生行视觉；原先禁止悬停高亮的约束被本次取代。
- 放弃：强制保持旧版行无悬停效果。
- 何时重新评估：需要定义行操作时。
- 对应：R2 / §5。

#### Q12：点击选中澄清
- 问题：点击后是否保留持久选中态？
- 决定：用户回答「保持 shadcn 表格默认状态」，未要求增加选中逻辑。
- 放弃：主动实现点击选中与详情。
- 何时重新评估：用户提出行操作时。
- 对应：R2 / §5。

#### Q13：默认状态的反例核实
- 问题：默认悬停但不主动设置持久选中，是否符合预期？
- 决定：用户明确答是；点击不导航。
- 放弃：点击行后保留选中态。
- 何时重新评估：需要行选中能力时。
- 对应：R2 / §5。

#### Q14：视口机制
- 问题：继续禁止视口裁剪，还是允许新表格本身的默认行为？
- 决定：用户要求保持 shadcn 原有组件能力，不特意启用或关闭任何能力，只做组件平替；旧版「全部构建、不虚拟滚动」不再限制新组件。
- 放弃：人为禁用原生视口机制以复刻旧实现。
- 何时重新评估：组件默认行为阻碍查看现有数据时。
- 对应：R2 / §5 / §6 决策 2。

#### 额外决定：预算选择与最终优先级
- 问题：访谈问题预算达到上限后，要拆分还是追加？
- 决定：用户澄清核心是「保持 shadcn 原有组件能力，只做组件平替」，不必再问重复问题；只有新的问题才考虑追加。本次没有追加新的访谈题。
- 放弃：拆分规格或为相同主题反复追问。
- 何时重新评估：出现确实不同的新产品决定时。
- 对应：§6 决策 2、3。此处为预算处理及用户主动澄清，不计入 14 个产品问题。

# Plan：补齐严格分析器配置

本执行计划（plan）只落实已批准的需求说明（spec）。R1–R4 是需求条目编号；方案确认（A）只审阅第 1–2 节。用户接受方案后，Agent 才填写第 3–6 节并另请开工确认（B）。

- Spec：`p00-006-strict-analyzer-config`（spec v1 / approved）
- Status：`approved`

## 1. 方案摘要

**用户会看到的变化**：

- 开发者使用现有编辑器分析和 `flutter analyze` 时，三个严格选项与八条既定 lint 生效；原有 `flutter_lints` 继续生效。
- 原有构建与平台目录排除项保持不变；`lib/`、`test/` 中手写代码不会被额外排除或用 `ignore` 隐藏新告警。
- 如新规则触发已有代码的告警，实现者消除这些告警后，页面显示、交互和演示数据仍保持原样。
- 格式、静态分析、测试均通过后，才能报告延期事项达到完成标准；遇到无关既有失败则停止，不报告完成。

**怎么做到**：Agent 只在项目现有分析器配置中补齐规范指定的语言选项与 lint，保留现有引入和排除项。现有 Flutter 工具直接读取配置；分析结果指出需要调整的既有 Dart 代码。Agent 仅消除由新增规则引起的告警，并用原有检查入口核对配置与行为，不新建 CI、分析器包装层或产品入口。

**为什么这么切**：配置与已有分析入口已经存在，不需要新增依赖或另一套检查链路。按实际新增告警限定代码调整范围，可以保持已交付页面的行为；与本次规则无关的既有失败留给用户另行决定。

**代价**：新规则影响哪些手写 Dart 文件，要在启用配置后才能确认；可能需要修改现有页面代码或测试。仅凭命令通过不能证明所有界面细节都未改变，还需对照变更与现有行为检查。遇到无关失败或必须改变原页面行为的修复时，Agent 停止，而不是扩大范围。

**需要用户决定的事项**：见 2.1 的本次追踪例外；用户接受方案 A 时，同时决定是否接受该例外。

**覆盖核对**：

## 3. 设计

### 3.1 结构与数据流

项目根的分析器配置是现有编辑器和 `flutter analyze` 的共同输入。Agent 保留 `flutter_lints` 引入及 `build/**`、`windows/**`、`macos/**` 三个排除项，只补上 FSD-11 指定的语言选项和 lint。现有入口读取配置后，分析结果指出受新增规则影响的 Dart 文件与具体告警；配置本身不读取页面数据，也不改变运行时状态。

Agent 以新增告警的实际位置决定是否调整现有手写 Dart 声明。未出现新增告警时不改 Dart。确有告警时，Agent 仅修改受影响的已有代码，保留既有页面输入、状态、输出、交互和演示记录。每个被改的 Dart 文件仍遵守第 2.2 节适用的文件头、已有需求锚点、依赖方向与命名；如果改动的声明落实本 spec 的 R3，遵守第 2.1 节约定的 R3 追踪边界。现有测试继续检查页面行为；若测试本身被新增规则命中，Agent 只处理该告警并保持测试断言原意。

格式检查、静态分析与测试的结果只用于判断本次交付是否满足 FUP-001 的完成标准。与新增规则无关的既有失败不进入代码修复任务；Agent 记录实际失败并停止称作完成。检查不引入新数据格式、CI 门禁、页面控件或网络入口。

### 3.2 决策

沿用第 1 节的现有分析入口和仅修复新增告警的边界；沿用第 2.1 节用户确认的本次 FSD-02 追踪例外。没有新的方案取舍。S1 结构归属不问：现有配置和现有 Dart 文件已限定改动位置；S2 数据流与状态不问：工具直接读取配置，不新增运行时状态。S3 依赖选型不问：已使用 `flutter_lints`，需求不允许新增规则与入口。S4 失败路径不问：需求 R4 已规定无关失败停止且不宣称完成。S5 检查方式不问：R4 已要求格式、分析、测试三项，现有入口可执行；检查任务由主 Agent 执行，并对照变更核对既有行为。S6 产物形态不问：FSD-11 已规定配置键和值，不产生新的用户文件格式或界面。U1 既有模式复用不问：现有分析器配置和现有测试可直接使用；不另建一套。

### 3.3 影响文件

现阶段只有以下文件确定必须修改。启用规则后才知道是否有现有手写 Dart 文件触发新增告警；这些有条件的最小调整由 T1 根据实际诊断处理，不预设文件名，也不把本节当作实现阶段必要辅助文件的封闭白名单。

- 操作：修改
- 职责：保持原有引入和三个排除项，增加 FSD-11 指定的严格语言选项和八条 lint。

### 3.4 边界

Agent 不修改规范正文、依赖清单、CI 或 formatter 配置，不改变原页面的显示、交互、演示数据与原测试的行为预期。未触发新增告警的 Dart 文件不因追踪形式而被修改。遇到与新规则无关的既有失败，或无法不改变既有行为地消除新增告警时，Agent 停止并报告，不擅自扩大范围。FUP-001 在实际配置与三项验证均满足前保持活跃。

## 6. 风险与回滚

#### 新增告警涉及既有页面代码
- 风险：消除静态告警的改动可能无意改变页面输出、排序或演示数据。
- 触发信号：T2 对照现有行为发现页面可观察结果有差异；T3 的页面相关测试失败；条件成立时 T4 的适用界面核对未通过或所需 macOS 入口不可用。
- 应对：只撤销引入行为变化的 Dart 调整，保留不改变行为的配置与必要修复；若找不到不改变行为的修复或必须执行的界面核对不可完成，停止并交用户决定，不报告已完成。

#### 检查遇到无关既有失败
- 风险：三项验证中的既有失败与启用规则无关，不能靠本需求修复。
- 触发信号：T3 的失败经对照新增规则和改动可判为无关；或基线已有同样的失败。
- 应对：保留实际失败结果，停止无关修复，FUP-001 不关闭；需要撤回时只撤销本次对 `analysis_options.yaml` 和实际受影响 Dart 文件的修改，保留原页面及已有测试的原始内容。

#### 配置未被按预期执行
- 风险：错误键名或错误层级使要求的规则未启用。
- 触发信号：T2 核对时发现缺项或值不是 `true`，或 T3 分析出现配置诊断。
- 应对：在 FSD-11 已明确的键与规则范围内更正配置并重做检查；无法在现有规范内解决时停止，不增补其他 lint 或排除项。撤回时恢复 `analysis_options.yaml` 原有内容，保留未受本次新增告警影响的 Dart 文件。

**对证**：开工确认 B，第 2/3 次独立核查。首次完整核查 V1–V8 发现一般问题 Q1（把页面行为不变误写成实现不得改）与 Q2（漏排条件性界面规范检查），无阻塞或轻微问题；在第 3–6 节修正后，第二次定向复核 Q1、Q2 及直接连带的任务依赖、检查入口、R3 映射与回滚，均已解决，当前遗留阻塞 0、一般问题 0、轻微问题 0。首次及正文修订后的最终 plan lint 均为 11 项通过。项目格式、分析、测试与桌面检查均未运行；新增告警实际位置及是否触发界面核对尚未验证。

## 决策

#### Q1：路线图放在哪里，占不占编号
- 问题：路线图是一份独立文件，还是放进 spec 目录。
- 决定：`specs/pNN-<slug>-roadmap.md`，与切片同层，不占 `NNN`。
- 放弃：放进独立目录，或多占一个 `NNN` 序号。
- 何时重新评估：一个阶段出现多份路线图时。
- 对应：R1 / §4

#### Q2：路线图对切片需求的约束力
- 问题：切片定义是否约束该切片 spec 的需求条目。
- 决定：约束。超出时停下，由用户新开会话修订路线图，再重读定义继续。
- 放弃：允许 spec 就地扩大范围，事后补路线图。
- 何时重新评估：切片定义反复出错时。
- 对应：R8 / §6 决策 1

#### Q3：可判断结果的粒度
- 问题：切片的「做完后用户能」写到多细。
- 决定：一句话可观察行为，例如「用户打开列表页并看到全部商品」。不写页面元素、接口和测试方式。
- 放弃：写成带验收清单的细条目，那等于提前写 spec。
- 何时重新评估：出现切片写完仍无法判断是否完成时。
- 对应：R2 / §4

#### Q4：重批规则
- 问题：哪些改动要重新批准。
- 决定：改切片边界、增删切片、调整顺序、改完成条件或整体不做，降级为 `draft` 重批；更新状态、补证据、追加决策与验收记录、勘误不降级。
- 放弃：任何修改都重批，或任何修改都不重批。
- 何时重新评估：出现只改一行却影响整体一致性的情况时。
- 对应：R8 / §6 决策 3

#### Q5：lint 的强度
- 问题：路线图要不要 lint，查到多细。
- 决定：要，11 项，只查结构、编号、引用和结论；不限制切片数量，不判断拆分好坏。
- 放弃：不做 lint，或把拆分质量也写进脚本。
- 何时重新评估：规则长期不触发或频繁误报时。
- 对应：R9 / §4

#### Q6：pNN 的语义
- 问题：`pNN` 是阶段号还是大需求号，是否需要两套编号。
- 决定：同一个东西。一个阶段就是一个大需求，统一用「阶段号」称呼，不另设编号。
- 放弃：阶段号与大需求号分开维护。
- 何时重新评估：一个阶段需要容纳两个大需求时。
- 对应：R10 / §4

#### Q7：存量 spec 是否回填
- 问题：`p00-001` 至 `p00-007` 是否补路线图或补头部字段。
- 决定：不回填，新切片从 008 起。
- 放弃：补建一份 p00 路线图覆盖存量切片。
- 何时重新评估：存量切片需要重开时。
- 对应：§5

#### Q8：本次是否走完整的 spec → plan → impl
- 问题：流程变更要不要按自己的流程走一遍。
- 决定：跳过 plan 与 review，用户逐段确认技能全文后直接落地。
- 放弃：先出方案文档、安排独立核查、再实现。
- 何时重新评估：路线图机制在下一个大需求出现执行偏差时。
- 对应：§6 决策 6

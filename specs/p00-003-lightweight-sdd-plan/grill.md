## 决策

Q1 `plan.md` 的结构取什么形状？候选：Kiro 式 design + tasks + research 三份；单文件"摘要 + 设计表 + 任务表"。
A: 单文件六节：方案摘要、约束与来源、设计、任务、R → 验证、风险与回滚。
   放弃：`research.md` / `design.md` / `tasks.md` 三份文档。
   何时重新评估：研究量增长到单节读不完时。
→ R5 / §5 / §6

Q2 长期技术偏好（组件库、密度）放在哪？
A: 放 `docs/standards/`，由 `steering.md` 索引；不进 `project.md`（会重复），也不每次口头交代给 plan。
   放弃：在 `project.md` 的技术栈里列 UI 库。
   何时重新评估：出现第二份需要跨 spec 生效的约定时，确认索引制仍然成立。
→ R8 / §6

Q3 临时技术约定放哪？
A: spec 第 4 节带 `**范畴**` 的 R 或第 6 节决策；只影响本 spec 的放 `plan.md` 第 2 节并标 `仅本次`。
   放弃：让 plan 自行决定后只在代码注释里留一句。
   何时重新评估：同一类临时约定第二次出现时，应升级为长效约定。
→ R8 / R9

Q4 "约束收集"与"研究"谁先？
A: 先预研（扫 `steering.md` 索引 + Grep 触碰面，输出必读/选读/不读清单），再精读、再访谈。正式项目规范很多，全量读会把预算烧在无关条款上。
   放弃：一次性把相关目录读完后再生效约束表。
   何时重新评估：索引规模超出单屏时。
→ R2 / §6

Q5 研究方式：一次性写长文档，还是访谈？
A: 访谈式，一次一问，逐层推进；plan 的问答允许给推荐（实现方式可以建议），推荐必须写代价。
   放弃：先写完整设计再交人审。
   何时重新评估：人明确要求"直接出稿"时（仍须标 `Agent 自定`）。
→ R3 / §6

Q6 人类确认放在哪个时点？
A: 两道：第 1–2 节写完停一次（`draft` → 确认后 `design-ok`），全部就绪再确认一次（`design-ok` → `approved`）。确认后由 Agent 独立完成设计与任务并自检。
   放弃：一次生成完整 plan 后单点确认。
   何时重新评估：摘要连续两次被整段推翻时。
→ R5 / §6

Q7 任务要不要 checkbox？为什么不只留表格？
A: 要。执行可能中断，`- [ ]` 支持从断点续做，也让 `plan_lint.py` 有稳定的解析锚点；但 checkbox 只表示断点，不作为完成证据，完成以 `sdd-review` 的命令输出为准。
   放弃：纯表格任务清单（无法续做），以及"勾满即完成"的判定方式。
   何时重新评估：出现多人同时执行同一 plan 时。
→ R6 / §6

Q8 约束冲突怎么解？一律中断补约定，还是按层覆盖？
A: 按层覆盖，越具体越优先：本次实现特例 > spec 第 4/6 节 > `docs/standards/*`。标 `覆盖` + 写明被覆盖条款 + 决策表给理由与失效条件；只有 plan 想推翻 spec 的 R 或第 6 节决策时才回 `sdd-grill`。
   放弃："规范与 spec 打架一律中断，先补约定"——把正常的上下位关系当成异常，`p00-001` 这种本次特例会被迫改规范。
   何时重新评估：覆盖条目长期不重评时，说明规范本身该改。
→ R8 / §6

Q9 技能要不要绑当前 Demo 工程？哪些文档算约束？
A: 不绑。模板、规则、脚本不出现具体语言、框架、构建命令或业务名词，示例用批量作业、格式转换这类通用场景；约束只认已生效的规范、spec 第 4/6 节与 `grill.md` 决策，项目自述类文档（readme）只是背景，不构成约束。
   放弃：照 Demo 工程的页面与测试命令写示例；把项目 readme 里的说明当作 plan 的约束来源。
   何时重新评估：出现第二种项目形态、示例需要区分场景时。
→ R10 / §5

Q10 `plan.md` 头部要不要记基线 commit SHA？
A: 不记。头部只有 `Spec` 与 `Status`；回滚写在风险表的「应对」里，表述为"撤销哪些改动、还原哪些文件"。`plan_lint` 反过来禁止头部出现基线 / commit / tag 字段。
   放弃：`基线 | HEAD <sha>` 这种写法——提交前不知道 SHA，填完 SHA 又改了文档，需要再提交一次，环上不可能收敛；个人项目也不依赖 Git。
   何时重新评估：项目引入多人协作并要求"从哪一版开始"可追溯时。
→ R7 / §6
